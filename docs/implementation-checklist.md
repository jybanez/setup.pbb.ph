## Security Checklist

- [x] Hub token can be supplied through environment variables.
- [x] Hub reports redact token material.
- [x] Runtime outputs stay under ignored `storage/`.
- [x] First-admin password can be supplied through an environment variable for unattended harness runs.
- [x] Database password can be supplied through an environment variable for desktop/runtime runs.
- [x] Cross-app secrets can be generated by Kit Setup and written to ignored runtime storage.
- [x] Secret reports expose only names, lengths, and short hashes.
- [x] Technitium API tokens can be referenced through environment variables and are not written to DNS reports.
- [x] Selected apps must have a trusted package manifest entry before package preparation passes.
- [~] App packages must come only from bundled or official trusted sources.
- [x] Package signatures can be verified before extraction with detached OpenSSL SHA-256 signatures.
- [x] PEM private keys must never be written to reports or logs.
- [x] Technitium API tokens must be accepted through environment variables and redacted from reports.
- [x] Visual installer must not allow arbitrary app installer upload.

## Separate Data Preparation Tool

The existing `populate` runner action remains available as the backend harness for app-owned data tools, but it should not be treated as a required installer stage.

Target product split:

- `Project Bantay Bayan Setup`: install and verify the node kit.
- `Project Bantay Bayan Data Prep`: prepare, import, refresh, or repair operational data after installation.
